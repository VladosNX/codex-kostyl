![Лицензия](https://img.shields.io/badge/license-MIT-blue)

Неофициальный мультиагентный графический клиент локальных AI-агентов для
программирования, написанный на Python и PySide6. Можно использовать встроенную
интеграцию с Codex CLI или подключать другие агенты по стабильному протоколу ACP
v1 через локальный stdio-транспорт.

Codex Kostyl предоставляет общий интерфейс для локальных проектов, сохранённых
диалогов, потоковых ответов, подтверждений действий и вложений. Для Codex
приложение напрямую использует `codex app-server`, поэтому его диалоги остаются
в стандартном хранилище Codex и доступны также из CLI. Для ACP набор элементов
интерфейса определяется возможностями, которые объявил выбранный агент.

> [!NOTE]
> Это независимый проект сообщества, а не официальный продукт OpenAI. Проект
> находится на стадии MVP и активной разработки.

## Для чего нужен этот проект

CLI-агенты для программирования уже предоставляют мощные терминальные интерфейсы.
Codex Kostyl предназначен для пользователей Linux и macOS, которым удобнее
работать с длинными диалогами, активностью агентов, подтверждениями разрешений,
вложениями, несколькими локальными проектами и разными агентами в одном нативном
окне.

Приложение не реализует собственный агентный backend. За аутентификацию, модели,
хранение истории, инструменты и песочницу отвечает выбранный CLI-агент.

## Возможности

- Локальные проекты на основе рабочих директорий.
- Переключение между встроенной интеграцией Codex и настроенными ACP-агентами.
- Создание, открытие, продолжение и копирование диалогов, если выбранный агент
  поддерживает эти действия.
- Потоковые ответы, reasoning, вывод команд, планы и изменения файлов.
- Динамические настройки модели, reasoning effort, режима сессии и других
  параметров, объявленных выбранным агентом.
- Режимы «только чтение», «рабочая папка», «полный доступ» и Plan Mode для
  Codex; ACP-агенты предоставляют собственные поддерживаемые режимы.
- Встроенные подтверждения команд, изменений файлов, сетевого доступа и
  дополнительных файловых разрешений.
- Вложения в виде локальных изображений и файлов.
- Очередь следующих сообщений во время активного хода.
- Интерактивные вопросы и подтверждение перехода от плана к реализации, если
  выбранный агент поддерживает эти возможности.
- Индикаторы контекстного окна и usage, когда выбранный агент передаёт эти
  данные, включая недельный лимит Codex.
- Markdown с таблицами, ссылками и подсветкой синтаксиса.
- Копирование и перенос предыдущих сообщений обратно в редактор.
- Уведомления рабочего стола и остановка активного хода.
- Способы входа, предоставленные агентом, включая ChatGPT и API-ключ OpenAI для
  Codex.
- Подключение нескольких локальных ACP v1-агентов с отдельными исполняемыми
  файлами и аргументами запуска.
- Установка ACP-интеграций из официального ACP Registry или последнего
  стабильного Release публичного GitHub-репозитория.
- Динамические функции, команды, способы входа, модели, режимы и настройки ACP;
  неподдерживаемые или временно недоступные функции остаются видимыми с причиной.

## Требования

- Linux или macOS.
- Python 3.11 или новее.
- Как минимум один поддерживаемый локальный backend:
  - Codex CLI 0.146.0 или новее в `PATH` и аккаунт ChatGPT/Codex либо API-ключ
    OpenAI; или
  - локальный исполняемый файл агента со стабильной поддержкой ACP v1 по stdio.

Перед установкой проверьте Python. Если планируете использовать встроенный
профиль Codex, также проверьте Codex CLI:

```bash
python3 --version
codex --version
```

## Быстрый старт

На Linux клонируйте репозиторий и запустите установку для текущего пользователя:

```bash
git clone https://github.com/VladosNX/codex-kostyl.git
cd codex-kostyl
./scripts/install.sh
```

`sudo` не требуется. После установки запустите **Codex Kostyl** из меню
приложений или командой:

```bash
~/.local/bin/codex-kostyl
```

Установщик создаёт изолированное виртуальное окружение в
`~/.local/share/codex-kostyl`, launcher в `~/.local/bin`, а также регистрирует
`.desktop`-файл и иконку приложения.

После запуска приложения:

1. Выберите встроенный профиль Codex или настройте ACP-агента.
2. При необходимости войдите способом, который предлагает выбранный агент.
3. Добавьте или выберите локальную рабочую директорию.
4. Настройте доступные модель, reasoning effort и режим запуска или доступа.
5. Опишите задачу и отправьте её выбранному агенту.

## Поддерживаемые агенты

- **Codex CLI** встроен в приложение и подключается напрямую к
  `codex app-server`.
- **ACP-агенты** добавляются как локальные профили, если они поддерживают
  стабильный ACP v1 по stdio. Для каждого профиля можно указать отдельный
  исполняемый файл и аргументы запуска.
- **Устанавливаемые интеграции** можно найти в официальном ACP Registry или
  установить из совместимого публичного GitHub Release.

Набор функций зависит от агента. Интерфейс строится на основе объявленных им
возможностей: неподдерживаемые модели, режимы, способы входа, действия с
сессиями, вложения или usage отключаются с пояснением, а не считаются доступными
по умолчанию.

### Подключение ACP-агента

Откройте меню аккаунта, выберите **Добавить ACP-агента…**, укажите название,
исполняемый файл и необязательные аргументы запуска. Профиль появится в селекторе
агентов и сохранится в `QSettings`. Один ACP-драйвер обслуживает любое число
таких профилей; одновременно работает только выбранный профиль.

Клиент использует стабильный ACP v1 поверх JSON-RPC 2.0 и локального stdio.
История, аутентификация и фактическое выполнение инструментов принадлежат самому
агенту. Интерфейс включает только объявленные или обнаруженные возможности:
например, список сессий, изображения, session modes, config options, slash-команды
и отображение usage.

На странице настроек **Агенты** также доступны официальный каталог ACP и
установка из GitHub Release. Декларативный пакет только описывает запуск уже
установленного CLI. Адаптеры протоколов скачиваются как проверенные ZIP-архивы и
работают отдельными ACP-процессами. Формат для авторов описан в
[документации интеграций](docs/agent-integrations.md).

## Другие варианты установки

### macOS

Готового `.app`/DMG пока нет. Установите CLI-агент, который хотите использовать,
и запустите приложение из виртуального окружения:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
codex-kostyl
```

Если при использовании встроенного профиля Codex его CLI не виден в `PATH`
графического процесса, выберите **Аккаунт → Указать путь к CLI…**. Пути к
исполняемым файлам ACP настраиваются отдельно для каждого профиля агента.

### Системная установка Linux

Системная установка для всех пользователей:

```bash
sudo ./scripts/install.sh --system
```

Приложение будет установлено в `/opt/codex-kostyl`, launcher — в
`/usr/local/bin`, а desktop-интеграция — в `/usr/local/share`.

Повторный запуск установщика обновляет существующую установку.

### Удаление

Удаление пользовательской установки:

```bash
./scripts/uninstall.sh
```

Удаление системной установки:

```bash
sudo ./scripts/uninstall.sh --system
```

### Структура проекта

```text
src/codex_gui/
├── agents/          # Контракты, профили, реестр, controller и ACP-драйвер
├── integrations/    # Каталог, GitHub-пакеты, валидация и локальное хранилище
├── app.py           # Запуск приложения и глобальные стили Qt
├── main_window.py   # Главное окно, редактор, таймлайн и диалоги
├── models.py        # Модели данных и политики доступа
├── rendering.py     # Отображение Markdown и вывода команд
├── rpc.py           # Транспорт QProcess и JSON-RPC-клиент
├── service.py       # Интеграция с Codex app-server и состояние
├── settings.py      # Постоянные настройки Qt
└── diagnostics.py   # Ротационный диагностический лог
```

Схема работы приложения:

```text
                         ┌→ CodexDriver → codex app-server
Интерфейс → AgentController
                         └→ AcpDriver   → ACP v1 agent (stdio)
```

`AgentController` владеет одним активным драйвером, но сам драйвером не является.
Реестр отдельно хранит виды драйверов и пользовательские профили: несколько
профилей могут использовать один `AcpDriver`. Драйвер публикует `AgentManifest`
со статической поддержкой функций, а controller вычисляет текущее
`FeatureState(supported, enabled, reason)`. Поэтому интерфейс различает «агент не
умеет compact» и «compact поддерживается, но пока нет открытой сессии».

Сообщения уходят как `AgentPrompt`, ответы преобразуются в общие события таймлайна,
а запросы разрешений — в `ClientRequest` с вариантами ответа агента. Детали
`codex app-server` и ACP не доходят до виджетов. Старые имена и сигналы Codex
временно сохранены как слой совместимости.

## Данные и конфиденциальность

- Сообщения не копируются в отдельную базу приложения. Для Codex они остаются в
  стандартном хранилище Codex; хранение ACP-сессий определяет выбранный агент.
- Через `QSettings` сохраняются пути проектов, выбранный агент, отдельные для
  каждого агента путь к CLI и параметры запроса, а также геометрия окна.
- Аутентификацией управляет выбранный агент или его драйвер. API-ключ OpenAI,
  введённый для Codex, передаётся Codex и не сохраняется в Codex Kostyl.
- Вложения передаются по абсолютным локальным путям и не копируются. После
  перемещения или удаления файла старый путь станет недоступен.
- Ротационный диагностический лог содержит события жизненного цикла и ошибки
  протокола, но не тексты запросов и ответов. Его путь определяется через
  `QStandardPaths` Qt.

Для сохранения отзывчивости интерфейс отображает не более 40 последних ходов и
300 элементов открытого диалога. Очень длинные сообщения и вывод команд могут
сокращаться визуально, при этом исходной историей продолжает управлять выбранный
агент.

## Модель безопасности

Режимы доступа и их фактическое соблюдение определяет выбранный агент. Встроенный
профиль Codex по умолчанию использует `workspace-write`, а требующие разрешения
действия показывает в интерфейсе. ACP-агенты предоставляют собственные режимы и
варианты подтверждений.

Для Codex доступны следующие предустановленные режимы:

- **Только чтение** — изменение файлов запрещено.
- **Рабочая папка** — запись разрешена только внутри выбранного проекта.
- **Полный доступ** — отключает файловую песочницу и использует политику
  подтверждений `never`. Включайте его только для доверенных проектов и задач.
- **Plan Mode** — использует штатный режим планирования Codex с песочницей только
  для чтения. После завершения плана интерфейс может начать реализацию в режиме
  доступа к рабочей папке.

Сообщения, отправленные во время активного хода, сохраняются в локальной очереди
и выполняются по одному. После успешного хода очередь продолжается, а после
ошибки или ручной остановки приостанавливается. Изменения модели, reasoning effort
и режима доступа применяются к следующему сообщению, но не меняют уже активный
ход.

## Известные ограничения

- На macOS пока поддерживается запуск из Python/venv без готового app bundle.
- Native Windows пока не поддерживается.
- Codex CLI требуется только для встроенного профиля Codex. Для каждого
  ACP-профиля должен быть установлен и доступен указанный исполняемый файл.
- Для очень больших диалогов интерфейс намеренно отображает только ограниченную
  недавнюю часть истории.
- Вложения зависят от исходных путей в файловой системе.
- Проект развивается вместе с протоколами Codex app-server и ACP; набор
  возможностей у разных агентов может отличаться.
- ACP поддерживается в стабильной версии v1 только через локальный stdio.
  Удалённые транспорты и черновой ACP v2 пока не поддерживаются.
- Клиент пока не объявляет ACP-агенту собственные операции терминала, чтения и
  записи файлов; агент должен выполнять их на своей стороне.
