Неофициальный нативный графический клиент Codex CLI для Linux, написанный на
Python и PySide6.

Codex Kostyl предоставляет интерфейс для работы с локальными проектами,
сохранёнными диалогами Codex, потоковыми ответами, подтверждениями действий,
вложениями и Plan Mode. Приложение напрямую использует официальный
`codex app-server`, поэтому диалоги остаются в стандартном хранилище Codex и
доступны также из CLI.

> [!NOTE]
> Это независимый проект сообщества, а не официальный продукт OpenAI. Проект
> находится на стадии MVP и активной разработки.

## Для чего нужен этот проект

Codex CLI уже предоставляет полноценный терминальный интерфейс. Codex Kostyl
предназначен для пользователей Linux, которым удобнее работать с длинными
диалогами, активностью агента, подтверждениями разрешений, вложениями и
несколькими локальными проектами в отдельном нативном окне.

Приложение не заменяет Codex и не реализует собственный агентный backend. За
аутентификацию, доступ к моделям, хранение истории, выполнение инструментов и
песочницу по-прежнему отвечает Codex CLI.

## Возможности

- Локальные проекты на основе рабочих директорий.
- Создание, открытие, продолжение и копирование сохранённых диалогов Codex.
- Потоковые ответы, reasoning, вывод команд, планы и изменения файлов.
- Динамический выбор модели и reasoning effort из списка Codex.
- Режимы «только чтение», «рабочая папка», «полный доступ» и Plan Mode.
- Встроенные подтверждения команд, изменений файлов, сетевого доступа и
  дополнительных файловых разрешений.
- Вложения в виде локальных изображений и файлов.
- Очередь следующих сообщений во время активного хода.
- Встроенные вопросы Codex и подтверждение перехода от плана к реализации.
- Индикаторы контекстного окна и недельного лимита, когда Codex передаёт эти
  данные.
- Markdown с таблицами, ссылками и подсветкой синтаксиса.
- Копирование и перенос предыдущих сообщений обратно в редактор.
- Уведомления рабочего стола и остановка активного хода.
- Вход через ChatGPT или API-ключ OpenAI средствами Codex.

## Требования

- Linux.
- Python 3.11 или новее.
- Codex CLI 0.146.0 или новее в `PATH`.
- Аккаунт ChatGPT/Codex или API-ключ OpenAI.

Перед установкой проверьте доступность инструментов:

```bash
python3 --version
codex --version
```

## Быстрый старт

Клонируйте репозиторий и запустите установку для текущего пользователя:

```bash
git clone https://github.com/VladosNX/codex-kostyl.git
cd codex-kostyl
./scripts/install.sh
```

`sudo` не требуется. После установки запустите **Codex Kostyl** из меню
приложений или командой:

```bash
~/.local/bin/codex-kostyl
```

Установщик создаёт изолированное виртуальное окружение в
`~/.local/share/codex-kostyl`, launcher в `~/.local/bin`, а также регистрирует
`.desktop`-файл и иконку приложения.

После запуска приложения:

1. Войдите через ChatGPT или укажите API-ключ OpenAI.
2. Добавьте или выберите локальную рабочую директорию.
3. Выберите модель, reasoning effort и режим доступа.
4. Опишите задачу и отправьте её Codex.

## Другие варианты установки

Системная установка для всех пользователей:

```bash
sudo ./scripts/install.sh --system
```

Приложение будет установлено в `/opt/codex-kostyl`, launcher — в
`/usr/local/bin`, а desktop-интеграция — в `/usr/local/share`.

Повторный запуск установщика обновляет существующую установку.

### Удаление

Удаление пользовательской установки:

```bash
./scripts/uninstall.sh
```

Удаление системной установки:

```bash
sudo ./scripts/uninstall.sh --system
```

## Запуск из исходного кода

Для разработки или временного локального запуска:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
codex-kostyl
```

Запуск пакета без console-script entry point:

```bash
PYTHONPATH=src python -m codex_gui
```

Установите тестовые зависимости и запустите тесты:


### Структура проекта

```text
src/codex_gui/
├── app.py           # Запуск приложения и глобальные стили Qt
├── main_window.py   # Главное окно, редактор, таймлайн и диалоги
├── models.py        # Модели данных и политики доступа
├── rendering.py     # Отображение Markdown и вывода команд
├── rpc.py           # Транспорт QProcess и JSON-RPC-клиент
├── service.py       # Интеграция с Codex app-server и состояние
├── settings.py      # Постоянные настройки Qt
└── diagnostics.py   # Ротационный диагностический лог
```

Схема работы приложения:

```text
Интерфейс PySide6 → CodexService → JSON-RPC → codex app-server → Codex CLI
```

## Данные и конфиденциальность

- Сообщения не копируются в отдельную базу приложения. Они остаются в
  стандартном хранилище диалогов Codex.
- Через `QSettings` сохраняются только пути проектов, последний выбор модели и
  режима доступа, а также геометрия окна.
- API-ключ передаётся Codex и не сохраняется Codex Kostyl.
- Вложения передаются по абсолютным локальным путям и не копируются. После
  перемещения или удаления файла старый путь станет недоступен.
- Ротационный диагностический лог содержит события жизненного цикла и ошибки
  протокола, но не тексты запросов и ответов. Его путь определяется через
  `QStandardPaths` Qt.

Для сохранения отзывчивости интерфейс отображает не более 40 последних ходов и
300 элементов открытого диалога. Очень длинные сообщения и вывод команд могут
сокращаться визуально, при этом исходная история продолжает храниться в Codex.

## Модель безопасности

По умолчанию используется режим `workspace-write`. Codex может записывать файлы
в выбранной рабочей директории, а требующие разрешения действия показываются в
интерфейсе.

- **Только чтение** — изменение файлов запрещено.
- **Рабочая папка** — запись разрешена только внутри выбранного проекта.
- **Полный доступ** — отключает файловую песочницу и использует политику
  подтверждений `never`. Включайте его только для доверенных проектов и задач.
- **Plan Mode** — использует штатный режим планирования Codex с песочницей только
  для чтения. После завершения плана интерфейс может начать реализацию в режиме
  доступа к рабочей папке.

Сообщения, отправленные во время активного хода, сохраняются в локальной очереди
и выполняются по одному. После успешного хода очередь продолжается, а после
ошибки или ручной остановки приостанавливается. Изменения модели, reasoning effort
и режима доступа применяются к следующему сообщению, но не меняют уже активный
ход.

## Известные ограничения

- Поддерживается только Linux.
- Codex CLI должен быть установлен локально и доступен launcher-у.
- Для очень больших диалогов интерфейс намеренно отображает только ограниченную
  недавнюю часть истории.
- Вложения зависят от исходных путей в файловой системе.
- Проект развивается вместе с протоколом Codex app-server.
